# 操作系统研讨课Project 4 Design Review

## 1 实验目标与当前基础

### 1.1 总体目标

P3已经建立了Shell、进程管理、同步与通信和双核调度，但不同程序仍依靠固定加载地址避免相互覆盖，同程序的多个实例也没有独立的全局数据。P4计划利用Sv39页表，让各进程使用相同的虚拟地址布局，并把这些地址映射到各自的物理页面。

本设计以C-Core为目标，覆盖任务一至五，并在双核下完成各阶段验证。初稿根据2026年11月11日的本地代码编写，2026年11月17日按决定将换页策略更新为Clock，后续代码也按该方案实现。当前分支为Project4，已合并课程P4框架。下文使用“计划”“拟采用”描述尚未实现的方案，不表示编译、QEMU或开发板测试已经通过。

| 任务 | 主要目标 | 计划验证方式 |
|---|---|---|
| Task1 | 双核启用虚拟内存，建立进程隔离并运行用户程序 | 两核启动提示、Shell、fly、重复启动同一程序 |
| Task2 | 缺页时动态分配页面，保留原有同步功能 | rw读写不同用户地址、多个lock实例 |
| Task3 | 物理页不足时在内存与SD卡间换页 | 限制用户页框数量，反复访问更大的虚拟地址集合 |
| Task4 | 同进程的多个线程共享地址空间、独立执行 | 三个mailbox进程，各有发送和接收线程 |
| Task5 | 不同进程通过共享物理页通信 | consensus及共享页获取、解除映射测试 |

## 3 Task1：内核页表与双核启动

### 3.1 Sv39页表结构

Sv39使用三级索引。一个虚拟地址由三级页号和12位页内偏移组成，每级索引占9位。每张页表占4KB，包含512个8字节PTE。普通4KB页面需要查到第三级叶子PTE；内核的2MB大页在第二级就作为叶子结束查找。

PTE记录物理页框号和访问属性。它不需要额外保存虚拟地址，因为虚拟页号已经决定了各级数组下标。非叶子PTE指向下一级页表，叶子PTE指向实际存放代码或数据的页框。

| 字段 | 计划用途 |
|---|---|
| PPN | 保存下一级页表或目标页框的物理页框号 |
| V | 表示PTE是否有效；V为0时结合软件记录判断未分配或已换出 |
| R、W、X | 分别表示读、写、执行权限；非叶子项均为0 |
| U | 用户页设1，内核页设0；非叶子项设0 |
| A、D | 访问和写入标记；Task1、Task2先置1，Task3由Clock清A采样，再由硬件或合法缺页处理置A |
| G | 初期不依赖全局TLB项，保持0，简化切换和刷新 |

PTE中的物理页框号从第10位开始，实际页面地址则按4KB对齐。因此设置PTE时不能把物理地址原样写入，也不能把内核虚拟地址当成PPN。

### 3.2 内核映射与页表位置

内核采用固定偏移映射：

```text
KVA = PA + 0xffffffc000000000
PA  = KVA - 0xffffffc000000000

物理地址0x50202000 → 内核虚拟地址0xffffffc050202000
```

这个转换只适用于内核直接映射区。任意用户虚拟地址必须通过所属进程的页表查询，不能直接减去同一个偏移量。

当前 `boot.c` 计划映射的高地址区域对应物理地址半开区间[0x50000000, 0x60000000)，共256MB，以128个2MB叶子项覆盖。根页表位于物理地址 `0x51000000` 。按当前框架的分配顺序，高地址映射的第二级表位于 `0x51001000` ，临时低地址映射的第二级表位于 `0x51002000` 。两组映射分别使用根表第257项和第1项，因此启动页表共占3页，即12KB。

高地址内核映射保留，临时低地址映射用于开启分页后的过渡指令和栈访问。boot.c当前为[0x50000000, 0x51000000)建立等值映射。跳到高地址后，只有确认两个核都已离开低地址启动代码与栈，才可以取消这组映射。

| 内核虚拟地址范围，左闭右开 | 计划用途 |
|---|---|
| [0xffffffc050000000, 0xffffffc050200000) | 固件及其使用的内存 |
| [0xffffffc050200000, 0xffffffc051000000) | 内核代码、数据及明确保留的启动区域 |
| [0xffffffc051000000, 0xffffffc052000000) | 启动页表、跳转表和相关保留区 |
| [0xffffffc052000000, 0xffffffc060000000) | 扣除保留区域后供动态分配 |

计划建立保留区域表，将各核启动栈、idle栈、页表、BIOS相关区域和读盘缓冲区排除在分配器之外。不能只让分配指针持续增长，否则最终可能覆盖读盘缓冲区或越过物理内存末尾。

### 3.3 启动过程

计划采用以下启动顺序：

```text
Bootblock装入内核到0x50202000
    → _boot设置本核独立的物理启动栈
    → 主核setup_vm建立页表，从核等待主核发布初始化结果
    → 每个核分别设置自己的satp并刷新本核TLB
    → 跳到高地址_start，切换到独立的内核虚拟地址栈
    → 主核清BSS并初始化全局状态，从核不再清BSS
    → 两核确认已进入高地址，取消临时低地址映射
    → 两核刷新TLB，分别打印进入VM内核的提示
```

在当前P3启动方式中，从核在Bootblock等待IPI。计划保留这一机制，由主核准备好页表、全局资源和从核运行状态后发送IPI。发布初始化结果前执行必要的内存屏障，保证从核看到完整页表。

核心编号计划沿用Bootblock保存到 `sscratch` 的值并在早期入口传递。当前新增start.S直接读取 `mhartid` 的方式需要调整，不能假定S态可以访问机器态CSR。BSS清零不能抹去仍需使用的启动同步信息，也不能清空已经建立的启动页表。

当前本地仍有几个待适配位置：Bootblock加载地址为 `0x50201000` ，head.S使用旧低地址栈，start.S只有一个固定栈顶，且main在唤醒从核之前调用 `kernel_brake()` 。计划先统一这些位置，第一阶段仅初始化必要的idle状态、输出和双核同步，使两核都打印VM提示并停住。创建Shell的 `init_pcb()` 会调用do_exec，应该留到用户页表准备好以后执行。

第一阶段完成后，再移除两核的停止点，启用用户进程。P4双核使用 `loadbootm` 启动，不沿用P2/P3的DASICS单核启动命令。

## 4 Task1续：用户地址空间与程序加载

### 4.1 地址空间对象

计划新增地址空间对象 `mm_struct` ，由PCB持有指针。不同进程分别拥有一个对象，同进程的线程共享同一个对象。对象保存根页表的内核虚拟地址、ASID、引用计数、用户页面记录、共享页映射、线程栈分配信息和正在使用它的核心集合。

创建进程时分配并清零一页作为根页表，将已经稳定的内核高地址根表项复制进去，随后建立用户区映射。这只是复制根表中的内核项，内核下级页表保持共享，不为每个进程复制全部内核页表，也不复制临时低地址映射。销毁进程时不能释放共享的内核下级页表。

pid0及从核idle使用启动内核页表，其根表的内核虚拟地址为 `pa2kva(PGDIR_PA)` 。用户地址空间的根表同样以KVA保存，写入satp时再转成物理页框号。

### 4.2 用户布局与权限

计划把Makefile的用户入口从当前的 `0x200000` 改为C-Core要求的 `0x10000` ，所有用户程序使用相同入口。主线程用户栈顶采用框架建议的 `0xf00010000` ，初始映射其下方一页，栈向低地址增长，入口SP保持16字节对齐。

普通用户页面使用4KB粒度。Task1先完整建立程序和初始栈所需的映射，Task2再为额外用户地址按需分配。不同进程的同一虚拟地址映射到不同物理页，不能继续使用P3“已有实例就直接复用可写映像”的策略。

用户叶子页设置U位，内核叶子页清U位。程序段的R/W/X权限计划依据镜像记录的段属性设置，用户栈和匿名数据页设为可读写、不可执行。若当前链接布局让代码与数据共页，则权限取该页所覆盖段权限的并集，避免在尚未拆分段时错误禁止写入。权限检查失败不能通过无条件增加权限来掩盖。

### 4.3 Loader与BSS

当前Loader按固定入口清空64KB并复制整份程序，不适合目标物理页不连续的情况。计划为Loader增加目标根页表参数，按下列流程加载：

1. 根据名称找到程序，验证入口、段范围、镜像偏移及大小。
2. 根据p_vaddr和p_memsz计算所需虚拟页面，调用 `alloc_page_helper()` 建立三级映射。
3. 新分配的数据页先清零，再逐页复制p_filesz范围内的文件内容。
4. p_memsz大于p_filesz的部分保持为0，正确初始化BSS，包括末页剩余部分。
5. 设置目标程序入口、用户栈和参数，全部成功后才发布到就绪队列。

计划同步修改 `include/os/task.h` 和 `tools/createimage.c` 中的镜像结构。记录至少包括文件位置、虚拟地址、p_filesz、p_memsz、权限与入口；若存在多个PT_LOAD段，则逐段保存，不能只把各段文件字节拼接后假定虚拟空间没有空洞。修改结构后必须重新制作镜像，不能让内核按新结构解释旧元信息。

alloc_page_helper() 返回目标页对应的内核虚拟地址，内核通过这个别名写入数据，不直接解引用尚未属于当前地址空间的子进程用户地址。按页基址调用此函数，需要写到页内某位置时再加偏移。

BIOS的SD读写接口传物理地址，内核访问缓冲区则使用KVA。计划包装读盘操作，单次不超过64个sector，使用保留的扇区缓冲区处理未对齐的起始偏移，向目标页面的复制也不跨物理页连续性边界。

### 4.4 参数传递与调度切换

参数复制保留P3的argc、argv约定，但计划拆成两个步骤：先把父进程参数读到有长度上限的内核缓冲区，再按子进程页表把字符串和指针数组写入子进程用户栈。指针数组保存子进程用户虚拟地址，结尾补NULL，不能保存KVA，也不能让子进程继续引用Shell输入缓冲区。跨页字符串要分段处理。

现有异常入口会清除SUM，因此不能仅在启动时设置一次就认为所有系统调用都能直接读写用户指针。计划通过统一的用户复制辅助函数查页表并使用KVA完成拷贝，必要时处理合法但未驻留的页面；若采用直接访问用户地址的路径，则仅在受控复制期间设置SUM，结束后恢复。锁、Mailbox等接收用户指针的调用也需要统一适配。

调度器选定下一个PCB后，依据其地址空间设置satp.MODE、ASID和根表PPN，再执行本核 `sfence.vma` ，随后完成上下文切换。内核代码、内核栈、PCB都处于公共高地址映射，因此切换页表不会让内核当前执行路径失去映射。初期每次切换都刷新，ASID复用也必须刷新，不能仅凭PID永久不重用就忽略ASID位宽。

向可执行页写入程序内容后，还计划对可能执行该程序的核心完成指令缓存同步。TLB刷新与指令缓存同步分别处理，不能用 `sfence.vma` 代替 `fence.i` 。

## 5 Task2：缺页与按需分配

### 5.1 页面状态

计划在地址空间中记录每个已管理虚拟页的状态：未分配、驻留、已换出，并保存权限、物理页框或swap槽位。没有PTE并不必然代表非法访问，需要先判断地址是否落在允许的用户区域。

Task2计划允许尚未占用的普通用户地址按需建立匿名可读写页，以支持rw指定地址，以及解除共享映射后再次访问原地址的课程测试。虚拟地址0、内核区、保留区和线程栈保护页不纳入该范围。对已有只读页的写入仍属于权限错误，不能变成新匿名页。

### 5.2 缺页处理流程

计划在异常表注册取指、读和写缺页处理，即原因码12、13和15。由 `scause` 判断访问种类，由 `stval` 取得故障地址，按4KB对齐后查当前地址空间。

```text
page_fault(regs, stval, scause):
    检查故障来自用户态还是内核路径
    检查地址合法性、区域类型和所请求的访问权限
    若为未预期的内核故障，输出诊断并停止错误路径
    若为非法用户访问，结束该进程并回收其资源

    在内核状态保护下重新查询页面记录及PTE
    若映射已由其他线程建立，重新核对权限与A/D位
    若页面已换出，调用换入流程，恢复原内容
    若为允许的首次匿名数据访问，分配并清零页框，建立映射
    若映射存在但A/D未满足访问要求，按权限补齐对应标志
    刷新相关TLB；涉及其他活动核时完成同步
    保持sepc不变，返回后重新执行原故障指令
```

缺页处理与ecall不同：ecall完成后跳过调用指令，而缺页处理成功后必须重试原指令。分配失败、swap读写失败和页表损坏要明确返回失败或终止进程，不能无限重试同一故障。

初期匿名数据页不提供执行权限。程序代码在exec时装入，非法地址取指不会被当作创建可执行匿名页的请求。若内核需要处理用户缓冲区的未驻留页，应从受控复制函数进入解析和换入流程，而不是把任意S态故障都解释为用户缺页。

Task2将继续复用内核中的互斥锁对象。锁表位于所有地址空间共有的内核映射中，同key仍得到同一个内核锁，不依赖两个进程拥有相同的用户物理页。

## 6 Task3：换页机制

### 6.1 替换策略与数据结构

换页替换策略确定采用Clock，后续代码直接围绕这一方案实现。它利用PTE中的A位近似判断页面近期是否被访问：扫描到A为1的页面时清A并给予第二次机会，扫描到A为0的可换出页面时选为victim。这样可以在不维护精确访问时间的情况下考虑访问局部性，但不保证对所有访问序列都有更低的缺页率。

计划维护物理页框表、用户页记录、Clock候选环、扫描指针和swap槽位表：

| 记录 | 保存的信息 |
|---|---|
| 页框记录 | 物理页号、所属地址空间和虚拟页、页面用途、驻留与固定状态 |
| 用户页记录 | 虚拟页号、权限、驻留页框或swap槽位、正在换页的状态 |
| Clock候选环 | 可换出的驻留用户私有页，节点可以定位所属地址空间及叶子PTE |
| 扫描指针hand | 指向下次检查的候选节点；跨替换保留位置，不每次从环头重新扫描 |
| swap槽位表 | 槽位占用情况与起始sector |

仅普通用户私有页参与Clock候选环。内核代码、页表、内核栈、分配器元数据、I/O缓冲区和共享页初期固定在内存中；正在读写或被内核复制的用户页也临时固定。用户栈可以参与换页，但须先完成上述用户复制与缺页支持，内核不能依赖栈页始终驻留。

新分配或换入的页面初始置A，插入hand之前，不改变已有候选的相对次序；空环首次插入后hand指向该页。普通访问不移动节点，只更新A。扫描时先保存下一节点再推进hand；选中的victim临时固定，换出成功或进程退出时从环删除，若删除节点正是hand则先调整hand，最后一个节点删除后hand置空。失败时恢复页面映射和候选状态，避免丢失节点或让hand指向已释放的记录。

```text
clock_select_victim():
    若候选环为空，返回无可用候选
    从hand开始，在有界扫描预算内逐项检查
        保存当前节点，hand推进到下一节点
        若页面正在I/O、被固定或已不再驻留，跳过
        若叶子PTE的A为1：
            清A，完成相关核的TLB同步
            保留该页并继续扫描
        否则：
            固定该页，返回该页作为victim
    若所有页面均不可换出，返回资源不足
    若因并发访问持续置A而未选中，返回重试状态
```

在没有新访问且候选状态稳定的情况下，若初始所有A均为1，最多扫描两圈即可选中页面。实际实现将扫描预算与候选数量关联，区分资源不足和需要重试，不在持锁状态下无限自旋。Clock只负责选择victim，换出、swap管理和物理页框复用仍由公共换页流程完成。

Task3不能一直把A固定为1。Clock清A后，需要执行相关的TLB同步，使后续访问能够重新被观察；若同地址空间在另一核活动，也需要按第6.3节同步。QEMU可能自动更新A，而课程开发板可能因A为0触发缺页，此时在验证原映射和访问权限后置A，写访问还按需置D，保留PPN与数据并重试原指令，不分配新页。后续扫描再清A，形成新的采样区间。A位的修改要遵守硬件更新和双核并发规则，不能用无保护的旧PTE覆盖新状态。

初期采用基本Clock，D位不参与victim选择；写回策略仍为完整保存页面。计划单独限制可换出的用户页框预算，页表等固定资源仍从保留好边界的页池取得。所有候选页都被固定或固定页池耗尽时明确失败，不能越界分配。

### 6.2 换出与换入

换出时计划先预留一个空闲swap槽，并阻止目标页被继续访问，完成相关核心的TLB失效确认，然后将4KB页写入8个连续sector。初期无论D位是否为1，都完整写出，简化后备副本的一致性。写入成功后记录该页为已换出，才能复用物理页框；失败时恢复原映射，不能丢弃唯一的数据副本。

换入时先取得可用用户页框，必要时由Clock选择另一个victim换出；再从记录的swap槽读回数据，恢复原权限和映射，置A并刷新TLB，将页面重新加入Clock候选环。读回成功并发布映射后释放原swap槽，下次换出重新写入。访问已换出的页时不能清零，否则会覆盖此前保存的数据。

swap区计划安排在最终组合镜像实际数据之后，按sector对齐，确保不覆盖Bootblock、内核、App Info及从第2048扇区开始的用户镜像。构建时在镜像尾部实际追加空间，并保存swap起始位置和容量；不能只扩大内核中的槽位计数而不扩大QEMU磁盘镜像。

### 6.3 双核一致性

 `sfence.vma` 只刷新执行它的核心。线程可以让同一个地址空间同时在两核运行，所以解除映射、降低权限、换出页面或复用页框之前，必须清除另一核心可能保存的旧TLB项。

计划先采用保守同步：记录地址空间的活动核，向其他活动核发送IPI，使其在内核安全点暂停使用该地址空间；修改映射后，两核分别刷新并确认，最后再允许页框复用和用户执行。对离线于该地址空间的核心，则保证下次调入时刷新。同步等待期间不持有对方必须取得的内核状态锁，TLB请求的应答路径也不能依赖该锁。

当前异常入口的持锁规则以及只使能定时器的路径需要为此调整，跨核TLB同步是计划新增的功能，不能把已有的启动IPI等同于运行期TLB同步。初期换页I/O采用同步方式并串行保护相关记录；不在中途释放状态锁后允许其他执行流回收正在I/O的页面。

## 7 Task4：线程创建、调度与回收

### 7.1 进程与线程的区别

进程主要拥有地址空间和进程级资源，线程是被调度的执行流。同进程的线程共享代码、全局数据和用户页表，但分别拥有用户栈、内核栈、寄存器现场、阻塞状态和线程ID。仅给两个PCB相同的程序入口不能实现线程共享。

计划继续以PCB作为调度单元，在现有字段后增加线程ID、所属进程ID、地址空间指针、线程栈区域、退出状态和join等待关系。PCB开头供汇编使用的字段顺序保持不变。主线程的进程ID沿用现有PID语义，新增线程ID用于pthread接口，ps计划同时显示所属进程和线程，避免把共享地址空间的线程显示成独立进程。

地址空间引用计数随线程加入和退出维护。用户栈虚拟区从统一的线程栈分配器取得，区间不能重叠；每个栈预留不可按需分配的保护页。页表中的映射建立后先完成必要同步，再把线程放入就绪队列。

### 7.2 创建与调度

计划保留课程用户接口：

```c
void pthread_create(pthread_t *thread, void (*start_routine)(void*), void *arg);
int pthread_join(pthread_t thread);
```

pthread_create的用户封装计划把入口与参数交给内核，内核返回线程ID后由封装写入thread指针。创建失败时约定写入无效ID，并保证部分分配的PCB、栈和引用均被撤销。

内核创建线程时不重新装入程序，也不清BSS。它关联当前进程的地址空间、分配独立双栈、继承CPU掩码，并初始化入口参数和异常返回现场。用户侧增加线程启动包装函数，先执行start_routine(arg)，函数返回后调用线程退出接口，防止返回到未定义地址。

线程进入现有共享就绪队列，继续由P3的状态锁和亲和性规则保护。切换到共享同一地址空间的线程时可以复用页表；初期仍允许统一刷新TLB，正确后再优化。P3每核tp指向当前PCB的方式继续保留。

### 7.3 join与退出语义

pthread_join计划只允许同进程内的其他线程等待，拒绝等待自己和无效ID。目标未退出则将调用者阻塞在目标等待队列；目标结束后唤醒等待者，再回收退出记录。虽然课程mailbox无限循环通常不会走到join，本设计仍计划补充有限线程测试，不能仅凭mailbox运行就认为join正确。

线程正常返回或thread_exit只结束自身；主线程main返回后的进程exit，以及按PID执行kill，计划结束整个线程组。进程级清理需要等待另一核上的组内线程停止后再回收整个地址空间。每个线程自己的内核栈仍沿用P3延迟回收，不能在当前栈上释放它。

计划区分“已停止执行、可以释放运行资源”和“join仍需查询的退出记录”。最后一个线程停止后释放地址空间，退出ID和等待结果可以由独立的小记录保存。kill整组时唤醒相关等待者，避免join永远等待已被移除的目标。

现有Mailbox按PCB记录打开引用，初期计划保留每线程的打开关系，线程退出时关闭自己持有的引用，不能因一个线程退出就关闭其他线程的邮箱。mailbox测试中的全局环形缓冲区在同进程线程间共享，在a、b、c三个进程间则相互隔离。双核下也需要检查缓冲区发布和读取的内存顺序，不能把volatile视为完整同步机制。

## 8 Task5：共享页与进程通信

### 8.1 获取共享页

计划实现 `sys_shmpageget(int key)` 和 `sys_shmpagedt(void *addr)` 。全局共享页表记录key、物理页框和映射引用数；每个地址空间单独记录共享映射的用户虚拟地址。

第一次使用key时分配并清零一页；后续使用同一key则映射已有物理页。内核在规定的用户共享候选区域中动态寻找空闲虚拟页，建立U、R、W映射，返回用户虚拟地址。两个进程返回的虚拟地址可以不同，但对应物理页必须相同。

“空闲”需要同时检查页表和软件记录。已换出页虽然V为0，仍占用虚拟地址，不能被共享映射覆盖。候选区域允许解除映射后按匿名缺页规则重新使用，这与consensus测试的要求一致。

### 8.2 解除映射与引用计数

shmpagedt计划验证地址属于当前地址空间的共享映射，再撤销该映射、完成两核TLB同步、减少引用计数。只有最后一个映射解除后，才释放共享物理页。线程共享同一页表，不为每个线程重复计算同一映射的引用；进程退出也要统一撤销未主动解除的映射。

解除后再次访问旧虚拟地址，缺页处理程序为它分配普通私有页，不恢复之前的共享关系。该地址被私有页占用后，再次shmpageget必须找到其他空闲地址。计划按这个顺序验证课程consensus中的先解除、再访问、再获取行为。

共享映射只解决数据可见性，不保证复合操作原子。consensus仍需要内核锁、Barrier与原子指令协调。当前测试配置为主进程加8个子进程，共9个参与者；每轮所有进程需要观察一致的选择结果，最终全部结束并释放共享页。

## 9 接口与资源回收约定

### 9.1 系统调用编号

当前合并已将共享页接口与P3扩展编号区分开。计划沿用以下约定，线程调用的编号则在实现时同步加入两侧头文件与内核注册表：

| 编号 | 接口 | 状态 |
|---|---|---|
| 56、57 | SHM_GET、SHM_DT | 已定义，具体服务待实现 |
| 58、59 | SET_SCHE_WORKLOAD、TASKSET | 保留P3扩展及现有注册 |
| 60、61、62 | 线程创建、join、线程退出 | 本文建议预留，当前尚未定义 |

新增系统调用需统一用户声明、封装、内核声明、编号和注册。当前系统调用表容量为96，仍需验证新增编号未被其他接口占用。

### 9.2 回收顺序

计划保留P3“先结束执行，再延迟回收当前栈”的原则，并扩展到整个地址空间：

1. 标记终止请求，不再发布新线程和新用户映射；从队列中撤销可直接停止的线程。
2. 等待另一核上的目标线程停止，清理线程等待关系、持锁与Mailbox引用，唤醒等待者。
3. 撤销私有页和共享页映射，完成活动核TLB同步，释放swap槽位与物理页。
4. 回收用户区下级页表和根页表，保留所有进程共用的内核页表。
5. 在旧执行流不再使用内核栈后释放该栈，按join语义保留必要退出记录。

共享页按映射引用回收，进程私有页按地址空间回收，线程独立栈按线程回收。创建失败也应按已完成的步骤反向撤销，不把半初始化对象加入就绪队列。

换页测试计划让同一地址空间的访问范围大于可用页框数，先写入每页不同的校验值，再反向和循环读回。单纯增加很多地址参数但不回访旧页，只能说明发生过分配，不能证明换入正确。

QEMU与开发板都需要验证，特别关注A/D位、TLB、指令缓存和BIOS读盘限制的差异。本文编写期间只进行了本地源码与课程资料核对，没有执行编译、运行、烧录或SSH测试。

### 11.1 对内核页表的理解

内核页表负责把内核虚拟地址映射到物理地址，并规定访问权限。开启分页后，内核的取指和数据访问也需要经过地址翻译。

本实验采用Sv39。普通4KB映射使用三级页表，每级通过9位索引选择一个PTE：

```text
根页表L2 → 中间页表L1 → 末级页表L0 → 物理页面
```

每张页表包含512项，每项8字节，因此每张表占4KB。内核采用2MB大页，在L1设置叶子PTE，实际只查询两级；这仍然属于Sv39，只是提前结束查找。

PTE主要保存物理页框号和属性。非叶子项指向下一级页表，R/W/X均为0；叶子项指向目标页面，并按用途设置合法权限。

| 字段 | 含义 |
|---|---|
| PPN | 物理页框号，指向下级页表或最终页面 |
| V | PTE是否有效 |
| R、W、X | 读、写、执行权限 |
| U | 是否允许用户态访问，内核页面清零 |
| A、D | 页面访问和写入标记 |
| G | 是否属于全局映射 |
| RSW | 留给软件使用的位 |

当前框架采用固定偏移映射：内核虚拟地址等于物理地址加上 `0xffffffc000000000` 。例如物理地址 `0x50202000` 对应内核虚拟地址 `0xffffffc050202000` 。该转换适用于内核直接映射区，不能代替用户页表查询。

按当前boot.c的分配顺序，根页表位于物理地址 `0x51000000` ，内核高地址映射的第二级表位于 `0x51001000` ，临时等值映射的第二级表位于 `0x51002000` 。因此当前启动框架共使用3张页表，占12KB；这不是所有三级页表固定占用的大小，而是当前映射布局的结果。

临时等值映射让CPU在开启分页后继续执行低地址启动代码。双核都进入高地址代码和栈后，才能撤销它，并分别刷新本核TLB。

### 11.2 用户页表如何创建，程序如何运行在虚拟内存上？

这个过程可以理解为：先给新进程准备一张自己的“地址对照表”，再找实际内存放程序，最后让CPU按照这张表运行它。计划采用以下五步。

第一步，为程序A分配并清零一张根页表。以后CPU运行A时，使用A的页表翻译地址。页表中也要加入公共内核映射，因为A执行系统调用时还需要进入内核；这些内核页面的U位为0，不允许用户态直接访问。

第二步，分配实际物理内存，建立对应关系。假设A认为自己的代码从 `0x10000` 开始，内核可以建立：

```text
A使用的虚拟地址0x10000 → 实际物理地址0x52003000
```

A只需要使用自己的虚拟地址，不必知道物理位置。另一个程序也可以使用 `0x10000` ，只要其页表把这个地址指向另一块物理内存，两者就不会互相覆盖。C-Core采用三级页表和4KB页，缺少下级页表时先分配并清零相应页表。

第三步，把程序内容装进去。内核从SD卡读取程序，将代码和数据写入刚分配的物理页面，需要初始化为0的部分清零，包括p_memsz大于p_filesz的BSS部分。写入时通过物理页面对应的KVA访问，不能直接拿子进程的 `0x10000` 当成当前可用的目标地址。连续虚拟页对应的物理页可能不连续，因此需要按页复制。

第四步，准备运行现场。给A准备用户栈，把参数字符串和argv数组复制进去，数组保存A自己的用户地址，并保证SP为16字节对齐。设置的主要内容为：

```text
从哪里执行：程序入口0x10000，写入sepc
栈在哪里：  A的用户栈，写入用户SP
传什么参数：argc和argv，写入a0和a1
运行身份：  用户态，设置sstatus.SPP为0
```

第五步，切换页表并运行A。调度器把satp指向A的根页表，完成必要的TLB刷新，再恢复A的寄存器现场，通过sret进入用户态。此时CPU从 `0x10000` 取指，就会根据A的页表，实际从 `0x52003000` 取得刚装入的代码。

### 11.3 page fault的处理流程

缺页异常不一定代表程序错误，需要根据故障原因分类处理。

| 原因 | 计划处理方式 |
|---|---|
| 合法匿名页面首次访问 | 分配并清零页框，建立映射 |
| 页面已经换出 | 从swap区读回原内容 |
| 合法映射的A/D位不满足访问要求 | 按硬件约定补置标志，保留原页框 |
| 地址非法或访问权限不足 | 拒绝访问，结束错误进程 |

计划从 `scause` 判断取指、读或写缺页，从 `stval` 获取故障地址，再查当前地址空间的PTE和软件页面记录。伪代码如下：

```text
handle_page_fault(regs, stval, scause):
    根据scause确定访问类型
    检查故障来源、地址范围和访问权限

    若为未预期的内核故障：
        输出诊断，停止错误路径
    若为非法用户访问：
        终止进程，返回

    在同步保护下重新查询PTE和页面记录
    若页面已经换出：
        取得页框，必要时通过Clock换出其他页
        从swap槽读回数据，恢复原权限及映射
    否则若为允许的首次匿名数据访问：
        分配并清零页框，必要时建立下级页表
        建立可读写、不可执行的用户映射
    否则若映射有效且权限正确，但A/D不足：
        补置此次访问需要的A/D位
        保留原物理页框和数据
    否则若映射已由其他线程正确建立：
        重新核对后使用现有映射
    否则：
        处理映射异常或权限错误

    处理分配或I/O失败，不能无限重试
    完成相关核心的TLB同步
    保持sepc不变，返回并重新执行故障指令
```

缺页成功处理后不能像ecall那样将sepc加4，因为原访存指令尚未完成。也不能把所有缺页都处理成分配新页，否则可能错误放行越权访问，或者丢掉已换出页面的原数据。

### 11.4 Page swap使用什么替换策略？

换页策略确定采用基本Clock。计划将可换出的驻留用户私有页组织为环形链表，维护扫描指针hand。节点保存或关联所属地址空间、虚拟页、物理页框和叶子PTE。

扫描时，若页面被固定或正在I/O，则跳过；若A为1，就清A、完成必要的TLB同步，并给予第二次机会；若A为0且允许换出，就选为victim。hand跨次保留位置，下一次从后续候选继续扫描。

清A后再次访问页面，由硬件或合法缺页处理重新置A。开发板触发A位异常时只补置标志，不重新分配或清零页面。扫描需要有界，所有候选都被固定时明确失败，持续并发访问导致选取困难时返回重试状态。

选出victim后，还需要执行实际换出：预留swap槽，阻止继续访问目标页并完成相关核TLB失效，将4KB数据写入SD卡，成功后记录页面已换出及其swap位置，最后才复用物理页框。初期D位不参与选择，每次完整保存页面。页表、内核栈、I/O缓冲区和共享页初期不参与换出。

### 11.5 如何实现和调度线程？需要修改哪些数据结构和函数？

计划沿用PCB作为调度单元，让同进程的线程关联同一个地址空间对象。它们共享代码、全局数据、堆和页表，但各自拥有用户栈、内核栈、寄存器现场和阻塞状态。

| 数据结构 | 计划新增或调整的内容 |
|---|---|
| PCB | 线程ID、所属进程、地址空间指针、线程栈及退出状态 |
| 地址空间对象 | 根页表、ASID、引用计数、页面和栈区域记录 |
| 等待关系 | join等待队列及退出结果 |

创建线程时先检查入口和参数，分配PCB并引用当前进程的地址空间，不重新加载程序或清BSS；然后分配独立双栈、构造初始现场、继承CPU亲和性，完成映射同步后加入就绪队列。用户入口需要包装，调用start_routine(arg)，返回后调用thread_exit，防止返回到未定义地址。

| 文件 | 计划修改的功能 |
|---|---|
| include/os/sched.h | 扩展PCB和地址空间关联 |
| kernel/sched/sched.c | 线程创建、调度、join、退出和回收 |
| kernel/mm/mm.c及头文件 | 用户栈映射、地址空间引用和释放 |
| tiny_libc/pthread.c | pthread_create、pthread_join及线程入口包装 |
| 系统调用头文件、封装和注册表 | 新增线程创建、等待和退出通路 |

调度器仍按PCB选择执行流。同地址空间线程之间可以复用根页表，切换到不同进程则需要切换satp并完成必要同步。

pthread_join等待目标线程退出后回收资源。线程退出只结束自身，进程exit或kill则按设计结束整个线程组。当前使用的内核栈必须延迟回收，最后一个线程停止后才可以释放共享地址空间；仍需供join查询的退出结果单独保留。

### 11.6 其他需要讨论的问题

1. 双核TLB一致性：一个核解除映射后，另一核可能仍缓存旧翻译。相关核确认失效前不能复用物理页框，等待确认时不能持有对方必须获取的锁。
2. 跨地址空间复制：Loader、argv和用户缓冲区访问都要区分用户VA、PA和KVA，连续虚拟地址不保证物理连续。
3. 共享页生命周期：不同进程可以将不同VA映射到同一物理页，按映射引用计数决定何时回收；共享数据仍需要锁或原子操作保护。
